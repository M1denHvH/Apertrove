### Существующая модель capability checks

`electron/camera-discovery.cjs` сохраняет общий приём Canon-моделей и известные import-only исключения EOS M/M2/M3/M5/M6/M10/M100. Это соответствует ограничению remote capture в справочнике, pp16–17. Остальные модели не становятся проверенно совместимыми из-за `capture: true`: это начальная политика допуска, дополненная результатом session, SaveTo, доступностью свойств и исходом команды.

`camera-worker.cjs:refresh` читает текущие свойства, вызывает `EdsGetPropertyDesc`, ограничивает список и передаёт `allowed`, `choices`, `descriptorCode`, `writable`. `camera-control.cjs:property` повторно проверяет descriptor, допускает только разрешённое значение, сериализует команды и сверяет read-back. Desktop `src/main.jsx:propertyControl` и remote `electron/remote/hud.js:[data-property]` используют эти данные; `preload.cjs` и `remote-server.cjs` проводят команды через существующий RPC. Неизвестные числовые значения сохраняются в choices с hex-подписью, поэтому отсутствие подписи нового enum не означает запрета реально выданного камерой значения.

`camera-capabilities.cjs:capabilityReport` уже отличает descriptor, временную недоступность, неизвестный исход команды и наблюдённые EVF/capture/AF/card результаты. Его `ready` — локальная диагностика конкретного сеанса, не постоянная сертификация модели. Успех регистрации event handlers означает только регистрацию, а не проверку всех типов событий.

## Обоснованное улучшение этого спринта

Добавлен **Kelvin WB через существующий descriptor-driven property path** (`electron/camera-values.cjs`, `camera-worker.cjs`, `camera-control.cjs`, `camera-capabilities.cjs`, `src/main.jsx`). `camera-worker.cjs` не запрашивает и не описывает `0x107`, пока WB не установлен на документированное значение 9; desktop предлагает только descriptor values, labels values как Kelvin и проверяет read-back в том же WB режиме. Статические пределы из справочника не добавлены в список допустимых значений. Нового FFI binding/структуры нет. `tests/native-production/kelvin.test.cjs`: **5/5** Node tests прошли с `--no-addons`, охватывая ID/label, worker refresh при разных режимах WB, descriptor gating, подтверждение записи, смену WB режима во время записи и единичную capability report строку. Это fake/source coverage, не native или hardware validation; Kelvin H2 на EOS 2000D пока **NOT RUN**. По официальному справочнику Kelvin control model-dependent и для EOS 2000D заранее не гарантируется.

**AEModeSelect в этом спринте не добавляется.** Это документированный scalar API для возможного будущего расширения того же property path, только если камера действительно возвращает непустой descriptor. Камеры с физическим mode dial остаются read-only по явному правилу Canon. Программная смена режима EOS 2000D не обещается.

EVF pan/click-to-focus, Bulb, новые структуры, guessed event constants и одновременное управление несколькими сессиями не выбраны. Их аппаратные/ABI предпосылки существенно шире текущего изменения. Число добавленных функций не является критерием готовности.

## Короткий план реальных проверок

N2 technical admission уже подготовлен и не повторяется здесь. Существующие pinned runtime/addon identities, Windows Job Object supervision, synthetic watchdog/admission results и manifest `ready: true, blockers: []` остаются подготовкой; `nativeLoaded: false`, выполнение **NOT RUN**. Правовой пункт остаётся одним отдельным `APPLICABLE_TERMS_UNRESOLVED`, без нового вывода о разрешении или запрете.

| Шаг | Узкий эксперимент и обязательный результат | Что не доказывает |
|---|---|---|

Сохранить реальные return codes, process-tree outcome, manifest и hashes. | Не проверяет camera structs, callbacks, FocusInfo, session, EVF, shutter или DATA-005. Source production fix не означает, что N2 уже выполнен. |
| **H1, EOS 2000D** | Отдельно разрешённый read-only session: discovery/выбор, OpenSession, ID/firmware/lens/battery, property size/type/value/descriptor и CloseSession. Использовать `cameraDiagnose`/`readOnly: true`; не обычный working connect, который меняет SaveTo/Capacity. Снять список ошибок и пустых descriptors, включая Kelvin/выбор режима, если добавлены. | Не подтверждает запись, remote capture, AF, EVF или каждую Canon-модель. FocusInfo распознаётся только с подтверждённым форматом, не по факту успешного чтения блока. |
| **H2** | Отдельно согласованные property writes с read-back и восстановлением, затем EVF first-frame/start/stop/restore, MF guard, AF/near/far с подходящим объективом. Каждую функцию отмечать отдельно; WIA и card import — отдельные явно разрешённые действия. | Никакого full shutter/burst/timer. Успех одной настройки не переносится на остальные режимы/объективы. |
| **H3** | Отдельно разрешённые shutter/RAW+JPEG/таймер/burst tests только в новом synthetic destination/session. Наблюдать press/release, файлы и registration, RAW+JPEG multiplicity, отмену/late transfer. DATA-005: controlled write/close/flush/registration/ACK faults и сверка NEW originals, recovery и исходов UNKNOWN. | Не повышать UNVERIFIED до CONFIRMED по тишине, количеству callback или одному успешному SDK code. Не использовать существующие фотографии как fault fixtures. |

Перед каждым новым аппаратным шагом фиксируются исходный commit, точные runtime/addon identities и условия эксперимента. Это последовательность реальной проверки продукта, а не новые уровни технического допуска для уже рассмотренных N2 компонентов. Legacy hardware scripts не становятся безопасными по имени, флагу или отключённой камере: см. [tests/TIERS.md](../tests/TIERS.md).

### Шаблон отчёта для дополнительных моделей Canon

Данные одной модели не распространяются на другую. Даже два одинаковых корпуса с разными firmware/lens/runtime должны иметь различимые записи. Строка совместимости содержит отдельно ожидание из source/reference и фактически испытанное поведение:

| Поле | Что записать |
|---|---|
| Идентичность | Commit Apertrove; OS/arch; runtime file/product version и SHA-256; addon version/hash; модель и firmware корпуса; объектив/adapter/AF switch; интерфейс соединения. Не публиковать личные USB/serial identifiers. |
| Условия | Дата; M/Av/Tv/P/Auto, still/movie mode; connected/EVF state; карта и SaveTo; разрешённый шаг N2/H1/H2/H3; isolated NEW destination. |
| Ожидание | `SOURCE/DOC EXPECTED`, reference section/page и source path; известное import-only ограничение или `MODEL-DEPENDENT / UNKNOWN`. Это не device-tested success. |
| Эксперимент | Одна функция: discovery/session; конкретный property read/descriptor/write/read-back; EVF; AF; lens drive; card import; capture; RAW+JPEG; shutdown. Пустой descriptor и Busy фиксировать как результат данного состояния. |
| Наблюдение | `DEVICE-TESTED PASS`, `DEVICE-TESTED FAIL`, `DEVICE-TESTED UNKNOWN` или `NOT RUN`; raw code; исходное/заданное/прочитанное значение; count/hash только новых synthetic files; logs/evidence location. |
| Восстановление | Final properties/SaveTo/EVF, session/worker exit, pending operations/transfers/ACK, отсутствие изменения originals, объяснение любого UNKNOWN. |

## Формулировка runtime

**EN:** Apertrove works with compatible Canon EDSDK runtime libraries installed separately by the user.

**RU:** Apertrove работает с совместимыми runtime-библиотеками Canon EDSDK, которые пользователь устанавливает отдельно.

Picture Style Editor — рекомендуемый потенциальный источник x64 компонентов Canon, не единственный допустимый runtime и не гарантия совместимости каждого его выпуска. Apertrove не включает и не перераспространяет библиотеки Canon. Отсутствие распространения DLL само по себе не устанавливает право стороннего приложения использовать их; применимые условия остаются отдельным нерешённым вопросом. Эта запись не меняет публичный README на неподтверждённое требование PSE.

# Публикация Apertrove на GitHub

Исходники публикуются из чистого GitHub-ready архива, Windows-сборка — отдельно в Releases.

## Перед первой загрузкой

- [ ] Выбрать владельца и имя репозитория, например `ваш_логин/apertrove`. Доступность внутри выбранного аккаунта проверяется GitHub.
- [ ] Просмотреть README, LICENSE и ограничения. MIT добавлена для собственного кода; Canon EDSDK распространяется отдельно по условиям Canon.
- [ ] Убедиться, что нет DLL/заголовков/руководств Canon, фото, библиотеки, личных путей, активных QR, ключей и серийных номеров.
- [ ] Установить Git, Node.js 24 LTS и GitHub CLI. Самостоятельно авторизоваться: `gh auth login`.
- [ ] Задать имя/email автора Git. Можно использовать свой GitHub noreply email; скрипт не выдумывает личность автора.
- [ ] Выполнить проверки и просмотреть экспортируемые файлы. Автопроверка известных секретов не заменяет просмотр.
- [ ] Выбрать видимость: по умолчанию public; для закрытого репозитория передать `-Visibility private`.

## Подготовка

Распакуйте исходники и откройте PowerShell в каталоге с package.json:

```powershell
npm ci
npm test
npm run build
node tests/designs.cjs
npm run preflight
npm run source:zip
.\scripts\Upload-GitHub.ps1 -Repository ВАШ_ЛОГИН/apertrove
```

Последняя команда только показывает план. Helper загружает отдельный allowlist-экспорт из `artifacts/github-upload`, а не весь рабочий каталог. Просмотрите его целиком перед отправкой.

## Загрузка

После проверки файлов и `gh auth login`:

```powershell
.\scripts\Upload-GitHub.ps1 -Repository ВАШ_ЛОГИН/apertrove -Publish
```

Helper повторяет preflight, создаёт свежий чистый экспорт, инициализирует ветку main и первый коммит, затем вызывает `gh repo create --source ... --push`. Существующий репозиторий не перезаписывается. В текущей разработческой сессии публикация автоматически не выполняется.

После загрузки:

- [ ] Проверить зелёный Windows checks в Actions.
- [ ] Включить Security → Private vulnerability reporting.
- [ ] Добавить описание и темы canon, camera, tethering, electron, photography.
- [ ] При необходимости включить Discussions и защиту main.
- [ ] Проверить картинки/ссылки README.

## Перед Windows-релизом

- [ ] Сверить версии package.json/package-lock.json, заголовок и CHANGELOG.
- [ ] Выполнить `npm ci`, `npm test`, `npm run build`, `npm run preflight`, `npm run package`.
- [ ] Проверить три дизайна в светлой/тёмной теме, свой цвет и сохранение настроек.
- [ ] Проверить сегментный LCD в обеих темах, реальные точки AF и режим физического MF.
- [ ] Создать фотосессию со своей папкой, открыть старую, проверить снимки и очередь после перезапуска.
- [ ] Проверить серию пресетов: ровно один кадр на шаг, EXIF/метки, остановку и восстановление exposure/AF/drive.
- [ ] Проверить доступные drive modes: чтение/запись/восстановление; реальный спуск — только при отдельном разрешении.
- [ ] Проверить аппаратную серию: отпускание, автостоп, разрыв связи и отсутствие конфликтующих команд.
- [ ] Проверить сетки/рамки/безопасные зоны на реальном изображении и в веб-пульте, без изменения оригинала.
- [ ] Проверить редактор панелей, изменение размеров и доступность всех элементов в минимальном окне.
- [ ] Проверить автора/copyright и экспорт всех прочитанных метаданных из старых и новых файлов.
- [ ] Проверить карточки оборудования офлайн и автоматическую загрузку фото производителя и локальный кэш; не включать чужие продуктовые фото в публичные материалы без необходимых прав.
- [ ] Проверить обновление старой библиотеки на резервной копии.
- [ ] С камерой: параметры с восстановлением, Live View, AF одним нажатием, неудачный AF/таймаут и освобождение команды. Тестовый спуск — только осознанно.
- [ ] С телефона: QR, фокус, параметры, остановка сервера и недействительность старого ключа.
- [ ] В архиве весь win-unpacked, лицензии зависимостей и ни одной DLL Canon/личной фотографии.
- [ ] Указать проверенные камеры и ограничения; не заявлять проверку всех моделей.
- [ ] Указать отсутствие подписи бинарника, приложить CHANGELOG и SHA256.
- [ ] Вручную создать тег/release, приложить Windows ZIP и SHA256. Исходники GitHub приложит автоматически.

Ручной workflow **Build Windows portable** создаёт Actions artifact; самостоятельно Release не публикует.
